# Milestone 14 — Optional hand tracking

The Hand Tracking Lab follows either workspace and is usable even if the historical backend is unavailable. Enable camera explicitly starts model loading and then requests video-only camera access. No camera request occurs on page load or from the camera-free engine check. MediaPipe's official HandLandmarker runs locally in a module web worker with CPU inference, up to two hands, 21 landmarks per hand, VIDEO mode, and 0.6 confidence thresholds. Frames are capped at 15/s with at most one frame in flight; stale frames are dropped. React updates only on detector results, not every animation frame.

The mirrored preview overlays numbered landmarks and connections. Readouts show handedness estimate and its score, five fingertip coordinates, a screen-plane orientation and measured inference duration. Orientation uses the wrist-to-middle-MCP vector, corrects for image aspect ratio, mirrors X, and measures clockwise from vertical. It is not full 3D palm orientation. Coordinates in the table remain in the original image system. Relative Z is a model estimate, not metric depth. Hand indices are not stable identities.

Stop, Escape, document hiding, session switching and unmount release video tracks, clear the preview, terminate the worker and discard queued results. ResourceScope also releases a camera stream returned after cancellation. Model startup has a 45-second timeout, camera permission/play has a 30-second timeout, and a 10-second no-frame watchdog releases a stalled live session. User can retry after denial, missing/busy camera, worker failure or disconnection. No automatic restart after hiding. Microphone is never requested.

Check tracking engine without camera loads the real bundled model and WASM, processes an artificial blank 64×64 frame in the real worker and reports the detected hand count, then terminates the worker. This tests runtime delivery and inference without accessing private camera data; it is not a live hand-accuracy test. Node tests cover cancellation/late resources, failure-tolerant cleanup, mirrored coordinates, orientation, malformed detections and camera-error messaging.

Runtime package is pinned to @mediapipe/tasks-vision 1.0.1; local model/WASM assets and source/hash provenance are in public/vendor/mediapipe. Model source: https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/index . Integration follows https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js . No third-party CDN call is required for detection. No recording, upload, persistence, dataset collection or gesture ML is implemented.

Files: src/domain/hands.ts, services/handProtocol.ts, workers/hands.worker.ts, hooks/useHandTracking.ts, components/handtracking/HandTrackingPanel.tsx, App integration, historical footer, CSS, package lock, local assets, tests, README and this document. Validate with npm test, npm run test:api and npm run build, then the camera-free browser engine check. Real webcam handedness, occlusion and frame rate require a person to enable the camera and show their hands.

Scope: this milestone provides hand detection and its debug overlay; it does not map gestures to replay, selection or camera control. Normal controls are unchanged. Rule-based gesture mapping and user-labeled gesture dataset collection should precede or accompany M15 gesture ML; no accuracy is claimed without those labeled examples. A secure context (HTTPS or localhost), camera permission, WebAssembly and worker/OffscreenCanvas support are required.

Verification completed 2026-09-23: all 57 frontend/domain tests and 32 backend tests pass. The production build succeeds. The in-app browser loaded the real model and processed a blank frame with zero detected hands while the camera remained off; retry and Escape-to-off were checked. Live webcam permission, actual hand detection and camera-device cleanup still require a user camera session.
